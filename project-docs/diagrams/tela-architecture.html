System Architecture

View 1 · Layers

Nine layers, three ways out

Each band is one layer of the platform, top to bottom from the browser to the runtime. Only three services reach the external resources on the right: Keycloak to Entra ID, the connector runner to Dataverse, and the LLM gateway to Azure OpenAI or Ollama.

View 2 · Containers and networks

Two containers reach outside, and only one of them holds source credentials

The proxy is the only published port. The connector runner is the only container on the sources network, and the LLM gateway is the only one on llm-egress. Everything else lives on the internal app network.

  1. 1HTTPS to the proxy. nginx routes / to web, /api to the API and /auth to Keycloak.
  2. 2Sign-in. Authorization code with PKCE; the API validates issuer, audience, signature and expiry against the JWKS.
  3. 3Federation. Keycloak brokers Entra ID; pmo maps the immutable Entra object ID, never e-mail, to a user.
  4. 4API calls. REST plus Server-Sent Events that stream an Ask turn step by step.
  5. 5Scoped, signed query. Compiled SQL or a Mongo pipeline, already scope-injected, signed by the query engine.
  6. 6Read-only source connection. Read-only identity plus a per-engine guard; optional SSH tunnel.
  7. 7LLM request. Typed prompts with schema, definitions and gold examples; no row data unless a tenant policy allows aggregates.
  8. 8Provider call. Only providers on PMO_LLM_ALLOWED_PROVIDERS; every call lands in the usage ledger.
  9. 9Secrets. API writes connection credentials; runner and gateway read them with read-only identities. The metadata DB stores only a reference.
  10. 10Metadata and vectors. One PostgreSQL with row-level security on tenant_id; pgvector HNSW for knowledge.
  11. 11Cache and queue. Result cache keyed by spec plus the viewer's scope hash; jobs enqueued for the worker.
  12. 12Background jobs. Introspection, knowledge indexing, exports rendered in Chromium, pack updates, outbox delivery.
  13. 13Local models. Ollama on the host for embeddings and the local planner (qwen3:8b on dev); the reranker inside the stack is wired but off by default.
View 3 · One Ask turn

The model proposes a spec; code checks it, scopes it and runs it

The language model never writes SQL for Ask. It produces a typed query spec over the approved data model, and only when the deterministic rules could not. Steps tagged LLM call the gateway; the others are plain code.

View 4 · Governed objects

Widgets store the question, never the numbers

Everything a viewer sees is recomputed from a spec under that viewer's scope. Publishing to a role is blocked until every widget on the dashboard uses certified definitions.

Controls

Where each guarantee is enforced

Row scope

Scope policies become predicates on every governed table reference, then the compiled query is re-parsed to assert it is scoped. Cache keys include the scope hash.

Field policy and masking

Hidden fields are dropped from the spec, and custom SQL that names them is rejected. Secret-named columns always return [REDACTED].

Read-only sources

Read-only database identity, read-only session, and a per-engine guard in the runner that blocks writes even if the compiler is wrong.

Tenant isolation

tenant_id on every tenant table, enforced by repository code and PostgreSQL row-level security with a transaction-local setting.

LLM boundary

One gateway, an allow-list of providers, pre-send leak scanning, typed outputs validated in code, and a ledger of every call's tokens and cost.

Audit

Append-only events for sign-in, connection changes, approvals, certification, publish, exports, policy denials and refused write requests.
